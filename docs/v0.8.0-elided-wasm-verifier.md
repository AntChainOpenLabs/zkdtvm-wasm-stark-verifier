# v0.8.0 elided WASM verifier design

## Goal

Expose a small, reusable WASM verifier whose runtime API is:

```text
verify(proof_bytes, program_vk_bytes) -> Result
```

The verifier must accept only the v0.8.0 elided compressed-proof wire form (normally about 250–270 KiB), bind the proof to the supplied program/core VK, and avoid rebuilding the complete native compression ladder on every call.

## What is bound to what

The compressed proof contains a terminal L4 proof and presents an L4 VK. The verifier compares that VK with its fixed release L4 VK and verifies the L4 proof. The authenticated L4 public values contain the digest of the supplied program/core VK, so the verifier also recomputes and compares that digest.

```text
fixed verifier release ── owns ──> L4 program + L4 VK
proof bytes            ── carry ─> terminal L4 proof + presented L4 VK
program VK bytes       ── hash  ─> digest checked against L4 public values
```

For a different ELF/program under the same verifier release, the API inputs that change are the program VK and its matching proof. If the L4 machine or verifier code changes, publish a new verifier artifact/package.

## Why the old WASM path was slow

The original byte-level entry point created a fresh `DTProver` for every verification. Its native backend reconstructed the fixed L1, L2, L3 and L4 recursion ladder and ran setup for the layers before checking the proof. On the tested Mac this made each WASM verification take roughly 11–12 seconds, although the actual proof check was only a small fraction of that time.

Compiler flags cannot remove this runtime construction because it is ordinary program work, not dead compile-time work.

## Minimal implementation

The backend adds one narrow abstraction, `NativeL4Verifier`, next to the existing native ladder code. It owns only:

- the terminal L4 verifier machine;
- the derived L4 preprocessing data required to restore the elided opening;
- the fixed L4 VK.

The release generator writes a 382,685-byte artifact containing the fixed L4 program, VK, schema version, Global146 identity and an integrity digest. At WASM initialization:

1. Decode and validate the embedded artifact.
2. Construct only the L4 verifier machine.
3. Run exactly one L4 setup, check that its generated VK equals the artifact VK, and retain the preprocessing data.

The WASM wrapper stores this object in a thread-local `OnceCell`. All calls in that worker reuse it. No L1–L3 machine is constructed in the runtime path.

The full serialized L4 PCS prover data was considered as a zero-setup artifact, but it is roughly 350 MiB because restoring an elided Merkle opening at proof-derived query positions requires the fixed codeword/tree data. Embedding it would turn a small verifier into an impractical download. The selected design trades a one-time approximately 1.8-second worker initialization for a roughly 3.0 MiB optimized WASM module and millisecond repeated verification.

## Verification sequence

For each call:

1. Deserialize `proof_bytes` and `program_vk_bytes` with the v0.8.0 wire format.
2. Require the proof's presented L4 VK to equal the fixed artifact L4 VK.
3. Validate the externally supplied program VK fields before any infallible digest helper is called.
4. Restore the missing first L4 preprocessing-opening batch from the cached fixed preprocessing data.
5. Require restoration to have occurred. If the batch was already present, reject the proof as non-elided.
6. Verify the terminal L4 proof.
7. Recompute the program VK statement digest and compare it with the authenticated L4 public values.
8. Validate the authenticated global interval.

The strict check in step 5 completely excludes the roughly 290 KB full-proof form from this verifier API. In the tested fixture, restoring that opening changes the serialized proof from 252,290 to 292,030 bytes, accounting for the full 39,740-byte difference.

## Change boundary

The implementation is intentionally concentrated in three places:

- `native-recursion/compress_dt.rs`: reusable L4 artifact and verifier logic, beside the existing ladder implementation;
- `zkdtvm-stark-verifier/crates/verify`: a small byte-oriented reusable facade and artifact generator;
- this WASM crate: embed, initialize once, and reuse the facade.

No proof format, Fiat–Shamir transcript, AIR, PCS algorithm or prover flow is changed. The existing prover-side elision remains authoritative. The backend was tested through a local path first; the final wrapper consumes the published backend `v0.8.0` tag.

## Release and test checklist

- Generate the L4 artifact with the exact backend revision used by the WASM build.
- Build `wasm32-unknown-unknown` in release mode with LTO and `wasm-opt -O3`.
- Verify a known elided `proof.bin` + matching `vk.bin`.
- Verify again in the same worker and record the reused-path time.
- Reject a modified proof and a modified/malformed VK without panic.
- Reject a valid but non-elided proof.
- Record artifact and fixture sizes and SHA-256 hashes.
